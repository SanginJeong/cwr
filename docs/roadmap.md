## 2. 검증 현황

### 확인한 것

- **DB 권한·규칙**: PGlite 테스트로 확인했습니다. 권한, 반복 일정, 초대·탈퇴, 게시판, 팀 게시판, 접속 상태가 대상입니다.
- **실제 Supabase**: 아래를 직접 실행해서 확인했습니다.
  - RPC 흐름(그룹 생성부터 할 일 조회까지)을 트랜잭션으로 실행하고 롤백
  - 비로그인 상태의 게시판 조회와 권한 거부
  - 임시 계정으로 팀 채널 접속, 상태 공유, 외부인 거부
- **화면**: 헤드리스 Chrome으로 Supabase 모드 팀 페이지를 캡처해 확인했습니다. PC·태블릿·모바일 레이아웃, 채팅 목업, 상태 메뉴, 상태 변경이 대상입니다.
- **인증**: 직접 브라우저 QA를 해주셨습니다(카카오 제외).

### 건너뛴 것 / 아직 확인 못 한 것

| 항목                                                                    | 이유                                               | 해야 할 일                                             |
| ----------------------------------------------------------------------- | -------------------------------------------------- | ------------------------------------------------------ |
| **로그인 상태 도메인 QA** (계정·팀·할 일·댓글·게시판·완료 기록)         | 직접 브라우저로 확인해야 함                        | [Phase 4 체크리스트](./backend-migration-plan.md) 진행 |
| **이미지 업로드** (Storage)                                             | Storage 정책은 PGlite 흉내 환경에서만 테스트함     | 위 QA에서 프로필·팀·게시글 이미지 업로드 확인          |
| **카카오 로그인 (Supabase 모드)**                                       | 버튼을 눌러도 로그인이 안 됨. 원인 미확인          | 증상 확인부터 (아래 4번)                               |
| 접속 상태: 실제 브라우저 두 개                                          | 헤드리스로 임시 계정 확인만 함                     | 일반 창·시크릿 창으로 두 계정 확인                     |
| 접속 상태: 10분 뒤 자동 자리 비움                                       | 10분을 기다리는 테스트를 하지 않음                 | 수동 확인, 또는 `PRESENCE_IDLE_MS`를 잠깐 줄여서 확인  |
| 접속 상태: 여러 탭, 네트워크 끊김 후 재접속, 1시간 뒤 토큰 갱신 후 유지 | 시나리오 테스트를 하지 않음                        | 수동 확인                                              |
| 로그인 상태의 테이블 직접 쓰기 (팀 수정·삭제 등 PostgREST 경로)         | 실제 DB에서는 SQL로 흉내 낸 검사만 함              | 도메인 QA에 포함                                       |
| DB 테스트를 실제 Supabase에서 실행                                      | 테스트는 PGlite + shim에서만 돎                    | 필요하면 Supabase 로컬(Docker) 또는 pgTAP으로 이전     |
| 새 컴포넌트 Storybook                                                   | StatusDot, MemberPanel, TeamChatWidget 스토리 없음 | 스토리 추가                                            |

> **정정 기록**: Phase 3 때 "Supabase 모드로 서버를 띄워 로그아웃 상태를 확인했다"고 했지만, 실제로는 `.env` 끝에 줄바꿈이 없어서 기존 API 모드로 떠 있었습니다. 그때 본 리다이렉트는 두 모드에서 똑같아 결과는 맞았습니다. 이번 화면 확인은 Supabase 모드로 제대로 실행했습니다.

## 4. 보류 중

### 카카오 로그인 (Supabase 모드)

- 확인한 것: Supabase 설정은 정상입니다. 같은 요청을 직접 만들면 카카오 로그인 화면으로 정상 이동합니다.
- 이상한 점: 앱에서 테스트하신 시간대에 PKCE 흐름 기록(`auth.flow_state`)이 생기지 않았습니다. 브라우저 요청이 Supabase까지 가지 않았을 가능성이 있습니다.
- 다음에 볼 것: 버튼을 눌렀을 때 증상을 확인합니다. 무반응·콘솔 에러인지, `?error=auth_callback`으로 돌아오는지, KOE 코드가 나오는지, `/login/kakao`로 가는지.
- 참고: 테스트하시던 시점에 개발 서버가 `.env` 변경 전 빌드였을 수도 있습니다. 위 정정 기록과 같은 종류의 문제입니다.

### 주간 리포트

- Claude API가 종량제라 보류했습니다. 대안은 LLM 없이 통계로 만드는 리포트입니다(완료율, 팀원별 기여, 요일별 추이, 밀린 할 일). 기존 PDF Export에 연결할 수 있습니다.

## 7. 기술 부채 / 정리할 것

- 원래 있던 lint 경고(사용하지 않는 변수, `useEffect` 의존성 등)
- `baseline-browser-mapping` 데이터가 오래됨(`npm i baseline-browser-mapping@latest -D`)
- 모바일에서 진행 상황 카드만 화면 끝까지 붙는 스타일(기존 `-mx`)이 아래 카드들과 다름
- 사이드바 메뉴에서 상태 항목은 왼쪽 정렬, 나머지 항목은 가운데 정렬. 구분선을 넣을지 검토
- 개발 모드에서 Next.js 개발 표시(N)가 사이드바 프로필 위에 겹침(개발 모드에서만)
- `.env` 끝 줄바꿈 (줄을 덧붙이는 스크립트가 앞줄에 이어 붙음)
