5. 의존성 정리 포인트

  • 버그① 토큰 재발급 경로가 존재하지 않음. lib/axios.ts의 401 인터셉터는 fetch("/auth/refresh-token")을 같은 origin으로 호출하지만, 이를 처리할 route.ts가 src/api/axios/auth/refresh/에 있어 Next 라우트로 등록되지 않습니다. 재발급이 항상 실패해 404 → 로그인 만료 처리로 이어질 가능성이 큽니다. src/app/auth/refresh-token/route.ts로 옮기거나 인터셉터를 백엔드 URL로 직접 호출하도록 바꿔야 합니다.
  • 중복날짜 라이브러리 2개 — date-fns + dayjs. dayjs는 utils/formatDate.ts의 format("YYYY년 M월 D일") 한 곳뿐. date-fns format(date, "yyyy년 M월 d일")로 교체하면 dayjs 제거 가능.
  • 중복애니메이션 라이브러리 2개 — gsap(+@gsap/react) + framer-motion. gsap은 랜딩 섹션 5개에서만, framer-motion은 Sidebar(전 페이지)·온보딩·게시판. 하나로 통일하면 번들에서 한쪽 제거 가능(랜딩의 ScrollTrigger 효과를 framer-motion useScroll/whileInView로 옮길 수 있는지가 관건).
  • 정리web-vitals는 DashBoardHeader의 INP 콘솔 로깅용 디버그 코드에서만 사용. 제거하거나 process.env.NODE_ENV === "development"로 가드.
  • 위치@tanstack/react-query-devtools는 dependencies에 있음. 프로덕션 빌드에선 자동으로 빠지지만 성격상 devDependencies가 맞습니다.
  • devDepssvgo는 어떤 설정·스크립트에서도 참조되지 않음. babel-plugin-react-compiler는 설치만 되어 있고 next.config.ts에 reactCompiler 설정이 없어 동작하지 않음 → 켜든지 제거.
  • 구조/dashboard 라우트가 두 폴더로 분산 — app/dashboard/(page·layout) vs app/(route)/dashboard/([id]·write·_components). app/dashboard/layout.tsx는 [id]·write에는 적용되지 않습니다.
  • 유지react-calendar(DatePicker), @react-pdf/renderer(dynamic import), axios, zustand(2개 store), react-hot-toast, clsx·tailwind-merge는 실제 사용 중이고 각각 대체재 중복 없음.
생성 방법: 각 page/layout/middleware 엔트리에서 정적 import·dynamic import를 추적하는 스크립트로 집계. 런타임 조건부 렌더링은 구분하지 않으므로 "도달 가능" 기준입니다.
